# 商城管理后台 - 内容管理模块开发指南

> 你已经完成了登录认证和日志管理，现在来开发第一个业务模块：**内容管理**。
> 本模块包含两个子功能：Banner 管理和公告管理。所有代码均参照项目现有规范编写。

---

## 为什么选这个模块？

| 原因 | 说明 |
|------|------|
| 完全独立 | Banner 和公告不依赖其他任何模块，不会互相影响 |
| 结构简单 | 每个表只有 5-6 个字段，没有复杂关联 |
| 涵盖完整流程 | 从数据库建表到接口测试，覆盖全链路 |
| 可复用模板 | 学会这个模块，其他模块（商品、营销等）照搬即可 |

---

## 开发路线图

```
第 1 步：执行 SQL 建表       → 2 张表

第 8 步：测试验证             → 启动 + Swagger + 前端页面
```

## 第 1 步：创建数据库表

在 IDEA Database 客户端中连接到 `mall_sys` 数据库，执行以下 SQL：

```sql
-- Banner 表
DROP TABLE IF EXISTS `content_banner`;
CREATE TABLE `content_banner` (
    `id`            bigint       NOT NULL AUTO_INCREMENT COMMENT '主键 ID',
    `title`         varchar(100) DEFAULT NULL COMMENT '标题',
    `image`         varchar(200) NOT NULL COMMENT '图片地址',
    `url`           varchar(200) DEFAULT NULL COMMENT '跳转链接',
    `sort`          int          DEFAULT '0' COMMENT '排序（数字越小越靠前）',
    `status`        tinyint      DEFAULT '1' COMMENT '状态：0-隐藏，1-显示',
    `create_time`   datetime     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`   datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`       tinyint      DEFAULT '0' COMMENT '逻辑删除：0-未删除，1-已删除',
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Banner 轮播图表';

-- 公告表
DROP TABLE IF EXISTS `content_notice`;
CREATE TABLE `content_notice` (
    `id`            bigint       NOT NULL AUTO_INCREMENT COMMENT '主键 ID',
    `title`         varchar(100) NOT NULL COMMENT '标题',
    `content`       text         COMMENT '公告内容',
    `is_top`        tinyint      DEFAULT '0' COMMENT '是否置顶：0-否，1-是',
    `status`        tinyint      DEFAULT '1' COMMENT '状态：0-下架，1-上架',
    `create_time`   datetime     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`   datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`       tinyint      DEFAULT '0' COMMENT '逻辑删除：0-未删除，1-已删除',
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='公告表';
```

### 表结构解读

**content_banner（Banner 轮播图）**

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | bigint | 自增主键 | 1, 2, 3 |
| title | varchar(100) | 标题 | "夏季促销" |
| image | varchar(200) | 图片路径 | "/upload/banner1.jpg" |
| url | varchar(200) | 点击跳转链接 | "https://example.com" |
| sort | int | 排序值 | 1（数字越小越靠前） |
| status | tinyint | 显示状态 | 1=显示，0=隐藏 |
| create_time | datetime | 创建时间 | 自动填充 |
| update_time | datetime | 更新时间 | 自动更新 |
| deleted | tinyint | 逻辑删除 | 0=正常，1=已删除 |

**content_notice（公告）**

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | bigint | 自增主键 | 1, 2, 3 |
| title | varchar(100) | 标题 | "系统升级通知" |
| content | text | 公告内容 | 公告正文 |
| is_top | tinyint | 是否置顶 | 1=置顶，0=不置顶 |
| status | tinyint | 上架状态 | 1=上架，0=下架 |
| create_time | datetime | 创建时间 | 自动填充 |
| update_time | datetime | 更新时间 | 自动更新 |
| deleted | tinyint | 逻辑删除 | 0=正常，1=已删除 |

### 关于逻辑删除

- 不是真正删除数据，而是把 `deleted` 字段改为 1
- MyBatis-Plus 自动处理：查询时自动加上 `WHERE deleted = 0`
- 好处：数据可恢复，历史记录保留
- 项目 `application.yml` 已配置：`global-config.db-config.logic-delete-field: deleted`

```java
package com.mall.mallsys.modules.content.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;
import lombok.EqualsAndHashCode;
import lombok.experimental.Accessors;

import java.io.Serial;
import java.io.Serializable;
import java.time.LocalDateTime;

/**
 * Banner 实体类
 */
@Data
@EqualsAndHashCode(callSuper = false)
@Accessors(chain = true)
@TableName("content_banner")
public class ContentBanner implements Serializable {

    @Serial
    private static final long serialVersionUID = 1L;

    @TableId(value = "id", type = IdType.AUTO)
    private Long id;

    private String title;

    private String image;

    private String url;

    private Integer sort;

    private Integer status;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    @TableLogic
    private Integer deleted;
}
```

### 2.2 注解含义

| 注解 | 作用 |
|------|------|
| `@Data` | Lombok 自动生成 getter/setter/toString/equals/hashCode |
| `@EqualsAndHashCode(callSuper = false)` | 不需要调用父类的 equals/hashCode |
| `@Accessors(chain = true)` | 链式调用，如 `banner.setTitle("xx").setStatus(1)` |
| `@TableName("content_banner")` | 指定对应的数据库表名 |
| `@TableId(type = IdType.AUTO)` | 主键自增 |
| `@TableField(fill = FieldFill.INSERT)` | 新增时自动填充 |
| `@TableField(fill = FieldFill.INSERT_UPDATE)` | 新增和修改时都自动填充 |
| `@TableLogic` | 标记逻辑删除字段 |

### 3.3 BaseMapper 内置方法一览

| 方法 | 作用 | 说明 |
|------|------|------|
| `save(entity)` | 新增 | 自动生成 INSERT SQL |
| `removeById(id)` | 根据ID删除 | 因 `@TableLogic`，实际是 `UPDATE deleted=1` |
| `removeByIds(ids)` | 批量删除 | 同上 |
| `updateById(entity)` | 根据ID更新 | 只更新非 null 字段 |
| `getById(id)` | 根据ID查询 | 自动加 `WHERE deleted=0` |
| `list()` | 查询所有 | 自动加 `WHERE deleted=0` |
| `list(wrapper)` | 条件查询 | 使用 LambdaQueryWrapper |
| `page(page, wrapper)` | 分页查询 | 返回 Page 对象 |

## 第 5 步：创建 Controller

### 5.1 ContentBannerController.java

**文件路径：** `src/main/java/com/mall/mallsys/modules/content/controller/ContentBannerController.java`

```java
package com.mall.mallsys.modules.content.controller;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.mall.mallsys.common.annotation.Log;
import com.mall.mallsys.common.result.Result;
import com.mall.mallsys.modules.content.entity.ContentBanner;
import com.mall.mallsys.modules.content.service.ContentBannerService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@Slf4j
@RestController
@RequestMapping("/api/content/banner")
@Tag(name = "Banner 管理")
@PreAuthorize("hasAuthority('content:banner:list')")
public class ContentBannerController {

    private final ContentBannerService bannerService;

    public ContentBannerController(ContentBannerService bannerService) {
        this.bannerService = bannerService;
    }

    /**
     * 分页查询 Banner
     */
    @GetMapping("/page")
    @Operation(summary = "分页查询 Banner")
    public Result<Page<ContentBanner>> page(
            @RequestParam(defaultValue = "1") Integer current,
            @RequestParam(defaultValue = "10") Integer size,
            @RequestParam(required = false) String keyword) {
        Page<ContentBanner> page = bannerService.page(
                new Page<>(current, size),
                new LambdaQueryWrapper<ContentBanner>()
                        .like(keyword != null, ContentBanner::getTitle, keyword)
                        .orderByAsc(ContentBanner::getSort)
        );
        return Result.success(page);
    }

    /**
     * 获取 Banner 列表（不分页，用于前端展示）
     */
    @GetMapping("/list")
    @Operation(summary = "获取 Banner 列表（不分页）")
    public Result<List<ContentBanner>> list() {
        return Result.success(bannerService.list(
                new LambdaQueryWrapper<ContentBanner>()
                        .eq(ContentBanner::getStatus, 1)
                        .orderByAsc(ContentBanner::getSort)
        ));
    }

    /**
     * 查询 Banner 详情
     */
    @GetMapping("/{id}")
    @Operation(summary = "查询 Banner 详情")
    public Result<ContentBanner> getById(@PathVariable Long id) {
        return Result.success(bannerService.getById(id));
    }

    /**
     * 新增 Banner
     */
    @PostMapping
    @Operation(summary = "新增 Banner")
    @Log("新增 Banner")
    public Result<Void> add(@Validated @RequestBody ContentBanner banner) {
        bannerService.save(banner);
        return Result.success();
    }

    /**
     * 修改 Banner
     */
    @PutMapping("/{id}")
    @Operation(summary = "修改 Banner")
    @Log("修改 Banner")
    public Result<Void> update(@PathVariable Long id, @Validated @RequestBody ContentBanner banner) {
        banner.setId(id);
        bannerService.updateById(banner);
        return Result.success();
    }

    /**
     * 删除 Banner
     */
    @DeleteMapping("/{id}")
    @Operation(summary = "删除 Banner")
    @Log("删除 Banner")
    public Result<Void> delete(@PathVariable Long id) {
        bannerService.removeById(id);
        return Result.success();
    }
}
```

### 5.2 Controller 逐行拆解

| 注解 | 作用 |
|------|------|
| `@Slf4j` | Lombok 自动生成 `log` 对象，可用 `log.info()` / `log.error()` |
| `@RestController` | 组合注解 = `@Controller` + `@ResponseBody`，返回 JSON |
| `@RequestMapping("/api/content/banner")` | 所有接口的基础路径 |
| `@Tag(name = "Banner 管理")` | Swagger 文档中的分组名称 |
| `@PreAuthorize("hasAuthority('content:banner:list')")` | 类级别权限，需要此权限才能访问所有接口 |

**构造器注入（Spring 推荐方式）：**

```java
private final ContentBannerService bannerService;

public ContentBannerController(ContentBannerService bannerService) {
    this.bannerService = bannerService;
}
```

比 `@Autowired` 更好的原因：
1. 字段是 `final` 的，不可变
2. 方便写单元测试
3. Spring 官方推荐

**接口设计对照表：**

| 接口 | HTTP 方法 | 路径 | 作用 | 权限标识 |
|------|-----------|------|------|----------|
| 分页查询 | GET | /api/content/banner/page | 分页查询（支持关键词搜索） | content:banner:list |
| 列表 | GET | /api/content/banner/list | 获取已上架 Banner（不分页） | content:banner:list |
| 详情 | GET | /api/content/banner/{id} | 查询指定 Banner | content:banner:list |
| 新增 | POST | /api/content/banner | 创建新 Banner | content:banner:add |
| 修改 | PUT | /api/content/banner/{id} | 修改指定 Banner | content:banner:edit |
| 删除 | DELETE | /api/content/banner/{id} | 逻辑删除指定 Banner | content:banner:delete |

**`@Log` 注解说明：**

```java
@Log("新增 Banner")
```

自定义注解，配合 `LogAspect` AOP 切面自动记录操作日志到 `sys_log` 表。参数为操作描述。

**返回类型 `Result<T>` 说明：**

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }     // 具体数据，add/delete 时为 null
}
```

### 6.1 Banner API — `api/content/banner.ts`

**文件路径：** `mall-sys-web/src/api/content/banner.ts`

```typescript
import request from '@/utils/request'

export interface ContentBanner {
  id?: number
  title?: string
  image: string
  url?: string
  sort?: number
  status?: number
  createTime?: string
  updateTime?: string
}

export interface BannerQueryParams {
  current?: number

}

export interface PageResult<T> {
  records: T[]
  total: number
  size: number
  current: number
  pages: number
}
```

### 菜单层级结构

```
内容管理 (id=动态, type=0 目录)
├── Banner 管理 (type=1 菜单)
│   ├── 新增 (type=2 按钮, permission=content:banner:add)
│   ├── 编辑 (type=2 按钮, permission=content:banner:edit)
│   └── 删除 (type=2 按钮, permission=content:banner:delete)
└── 公告管理 (type=1 菜单)
    ├── 新增 (type=2 按钮, permission=content:notice:add)
    ├── 编辑 (type=2 按钮, permission=content:notice:edit)
    └── 删除 (type=2 按钮, permission=content:notice:delete)
```

### 菜单字段说明

| 字段 | 说明 |
|------|------|
| parent_id | 父级菜单 ID，一级菜单为 0 |
| type | 0=目录，1=菜单（有页面），2=按钮（无页面） |
| permission | 权限标识，格式 `模块:功能:操作` |
| path | 路由路径 |
| sort | 排序值，越小越靠前 |

## 常见问题 FAQ

**Q1: 编译报错 "cannot find symbol: class ContentBanner"**
→ 检查 `package` 声明是否为 `com.mall.mallsys.modules.content.entity`，import 路径是否与文件实际位置一致。

**Q2: 启动报错 "No qualifying bean of type ContentBannerMapper"**
→ 确认 `ContentBannerMapper.java` 上有 `@Mapper` 注解。项目中 `@MapperScan` 被注释了，所以每个 Mapper 都要单独加 `@Mapper`。

**Q3: 调用接口返回 403（无权限）**
→ 确认已执行第 7 步的菜单 SQL，并重新登录获取新 Token（权限信息在 Token 里）。

**Q4: 分页查询返回的数据不正确**
→ 确认 `MybatisPlusConfig.java` 中已配置 `PaginationInnerInterceptor`。未配置分页插件时，`page` 参数不生效。

**Q5: 删除后数据还在数据库里**
→ 正常！逻辑删除只是把 `deleted` 改为 1。执行 `SELECT * FROM content_banner WHERE deleted=1` 可查看已删除数据。

**Q6: 前端页面 404**
→ 检查 `router/index.ts` 中是否添加了路由，且路径与菜单 `path` 字段匹配。

**Q7: 前端提示 "找不到模块 '@/api/content/banner'"**
→ 检查文件路径是否为 `src/api/content/banner.ts`，目录需先创建。

## 下一步学什么？

完成内容管理后，建议按以下顺序继续：

| 顺序 | 模块 | 难度 | 原因 |
|------|------|------|------|

| 2 | **设置模块** | ★★★★☆ | 快递公司 + 数据字典，引入简单关联 |
